# Hidden types: forensics for classes the registry does not list

[Class reference](classes/index.md) · [Object model](../engine/object-model.md)

The class-descriptor table lists 199 classes. Sucker Punch's source almost certainly had more types: abstract intermediates without a descriptor, C++ helper classes, and polymorphic structs. This page collects the evidence. **Every inference here is a HYPOTHESIS** unless tagged otherwise; the data under each one is exact (ELF). Generated by `gen_classes.py`.

## A. Siblings sharing identical overrides their registered parent lacks

If two or more children of P all put the *same* function in a slot where P has something else (or P has no such slot), the simplest explanation is an unregistered intermediate class between P and them that defines that slot. Alternative explanations: the children call a shared helper that was installed directly in each class (C++ allows `virtual f() = X::f`-like reuse only via inheritance, so identical function *addresses* in unrelated classes usually mean either inheritance or a non-member function cast into the vtable, which Sucker Punch's C-style method tables do). **Exclusive** slots use a function no vtable outside the group's subtrees uses; shared generic stubs (empty functions) are counted but are weak evidence. Strength: strong = ≥3 exclusive slots, or new slots + ≥2 exclusive; medium = ≥1 exclusive.

## B. Vtables and descriptor-like tables not claimed by a registered class

### B1. Registered getters returned by more than one vtable

Slot 6 identifies the class a vtable belongs to (a slot-6 function outside the getter block that returns a descriptor record also counts: a *duplicate getter*). When several vtables report one registered class, the extra ones are either (i) unregistered subclasses that inherit that class's `Pclassinfo`, or (ii) duplicate emissions of the same vtable with a duplicate getter copy (GCC 2.9x emits a vtable and its inline virtuals in every TU when the class has no out-of-line virtual; such copies are unreferenced). The table facts are `[C:static]`; the reading is HYPOTHESIS. Vtables never stored by any code are typical of abstract bases (their constructor was inlined into the derived one and the store eliminated) or of dead duplicates.
